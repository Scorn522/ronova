## 根因与实现

用户世界的 canonical Root 与旧 Ledger 的 Realm、epoch、Owner、Tombstone、lifecycle 事实一致，但快照组装使用不同的 persisted/shadow-persisted 描述。r57 在已完成 cutover 后仍用旧镜像完整快照/哈希否决 Root，导致正常数据被拒绝。停服又调用创建型 runtime()，重复抛出同一异常。

- `LocalDominionStore.openWorld` 是生产和回归共用的文件启动入口，先读取和验证 `ronova/durable-root-v1.bin`，有效 Root 独立决定 Realm 和持久状态。
- 已 cutover 的 `promoteFromLegacy` 只确认 Root 自身有效及持久恢复，不反向依赖镜像。实际坏 checksum/schema/Realm/journal/资格/效果记录仍拒绝。
- 缺 canonical 文件且存在已 cutover 的 shadow 或 Ledger mirror marker 时拒绝启动。不存在 cutover 证据时，旧 Ledger/shadow 的首次迁移继续严格核验。
- 镜像比较使用持久事实集合：Realm、epoch、Owner、墓碑全字段及生命周期记录，忽略集合顺序和派生 reason。没有改写 Root 原描述、历史哈希或回执。
- 旧镜像缺失、过期、损坏、错 Realm 时由有效 Root 重建。两份 SavedData 通过明确安装入口登记；shadow 镜像标记 dirty，确保修复实际保存。
- 覆盖镜像前保存其原字节，备份按 SHA-256 命名；每世界诊断备份上限 128 文件 / 64 MiB。无法保存备份时保留原镜像文件，关闭本次镜像写入并报告状态，canonical Root 继续工作。
- 镜像 NBT 读取有 64 MiB 文件/内存预算，支持 gzip 和未压缩 SavedData wrapper。镜像新增派生 `durable_root_mirror` 标记，不改变 canonical Root schema。
- 新增 `getIfPresent`；停服 Mixin、JudgmentEngine、SpawnFirewall 使用已有实例。失败构造保存原异常、回收部分注册资源且不隐式重试；已释放的 server slot 不重新创建。
- 退出清理用 finally 和逐项资源释放保证后续清理执行，原始初始化异常保留；Root 在其他运行资源之前打开。

格式继续为 Root schema 5 / journal 3 / effect 1 / qualification 1 / policy 3 / protocol 9；Native DLL 未改。
