## 本批行为

- Root 写文件失败后保留原工作图像和 command journal，运行时读取继续使用最近已获持久 ACK 的 `ReadHead`。snapshot、epoch、commit index、策略和 Owner/Tombstone 查询不会提前暴露未确认变化。
- 原图像恢复写入成功后一次切换读取头。`RootCommandBus` 的初始化和后台发布重试使用同一串行入口；背景重试不能发布尚未确认的图像。
- OwnerRegistry、TombstoneStore、EpochClock 的兼容读取返回副本，修改返回对象不会成为第二个 Root writer。已有未知 lifecycle intent 仍保留并可诊断，不会因读取头隔离而被忘记。
- 新增 `SubjectKey = (RealmId, subjectId)`。本批在既有 Store Realm 内明确映射原 exact UUID；metadata 不进入该键，原 Tombstone 命中及精确解除规则继续使用相同身份域。
- `TargetEpoch` 改为 SubjectKey-qualified 的 per-subject generation。新终结、显式解除、再次终结分别推进该主体的代际；已解除主体仍保留代际记录，其他主体不跟随全局事务编号一起推进。
- 一个非空 JudgmentBatch 的全部资格变化与原 Judgment/Tombstone、command journal 同图提交：一个全局 epoch transition、一个 commit index、一个 receipt。任何目标失败时 staged 资格不会半提交。
- receipt 保存该次提交实际发放的资格。以后恢复旧命令时返回原资格；不会根据当前 snapshot 把旧回执续租为新代际。
- 生产 `JudgmentExecutor` 在调用旧物理链前，同时检查 receipt membership 与 Root 当前 TargetEpoch。解除或新终结后，旧 receipt 不能再次通过这一入口。
- `EffectKey` 固定 command、SubjectKey/TargetEpoch、semantic operation/slot；plan revision 和 attempt 不进入 key。当前只实现类型与回执归属合同，尚未上线通用 effect journal。

## 格式与迁移

| 项目 | r56 |
|---|---|
| Root NBT schema | 4 |
| command journal format | 3，继续每个 journal 只持有一份当前 snapshot |
| qualification extension | 1，排序、唯一 SubjectKey、Realm/状态核对、独立摘要 |
| strength policy / protocol | 3 / 9 |
| Native DLL / Native snapshot wire | 本批未改，qualification 尚未传播到 Native/task/packet 全链 |

Root schema 1–3 读取后以原 Store Realm + exact UUID 建立显式 legacy baseline，代际为 0；不能由历史全局 epoch 推算新的主体资格。
旧 command id、payload hash 和 receipt 语义保留，历史 receipt 的 qualifications 为空。旧 lifecycle claim 继续防止重复 opaque 入口，不能迁移成效果完成证明。
首次新的资格事务才发放 generation 1，之后不复用旧值；溢出拒绝。无 UUID 的观察不会被随机分配为 durable SubjectKey。

新 schema 在世界副本上进行实机迁移；旧 r55 不能保证回读 schema 4 / journal 3。原 r55 JAR 和源码归档保留在 `build/libs` 与 `validation/7.17/baseline-r55`，未覆盖。

`SubjectIdentity` 当前仍是既有观察/迁移 DTO。完整 incarnation resolver、BindingRevision、per-domain OwnershipRevision、元数据迁移冲突处理与 expected-revision qualification payload 还未完成。
本批 batch 的冲突检查继续使用既有 shared expected DominionEpoch，并在 Root 内补充受保护 Owner 的逐目标拒绝。
