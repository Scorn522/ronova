## 实现

- 每个 ServerPlayer/Connection 对应独立 stream UUID、context revision 和递增投影 revision；晚到的旧 player release 不删除新连接登记。
- OwnerState 同时发布 Realm、stream、context revision 和 Root Owner 授权版本。客户端拒绝旧 context、旧 Owner revision 和同版本冲突。
- ProjectionFrame 绑定 Realm/stream/context、revision/baseRevision、Root epoch、操作和分片索引；单片最多 128 marks，最多 512 片/65536 marks，字符串与数值有界。
- 初始/重同步快照必须完整收齐后一次发布；片段可乱序到达，相同重复片不会改变结果，冲突片保留原已提交视图并请求重同步。
- APPEND/REMOVE/CLEAR 必须接在当前 revision 后，旧版本或旧 Root epoch 不生效；不同 Realm/stream/context 不可覆盖当前状态。
- 缺片超过 2 秒或增量断档后，客户端按 1 秒节流请求 Root 当前全量快照，服务端也限流；新快照可跨越缺失的增量版本。
- 网络 handler 的客户端排队回调检查原始 Connection 仍是当前活跃连接；断开时清理投影，旧排队消息不能绑定新连接。
- 发布方从当前 Root projection 取 mark；不直接信任调用方提供的旧 mark。若请求 remove/clear 与当前 Root 不符，改发当前全量视图，不发送错误撤销。
- 只有组装器提交成功后才统一替换 ClientQuarantineView；owner/feedback 也受连接或版本边界约束。

## 验证与边界

新增 ProjectionStreamSelfTest 覆盖多片原子提交、重复/冲突、精确 remove、clear 后旧 append、版本断档、缺片超时、Owner revision、stream/context 更换和断开清空。协议/结构测试更新为六个 packet、OwnerState 六个字段，并保留原 Realm/撤销/统一发布要求。

实际 Forge fixture 通过 Root batch 生成 129 个受控投影目标，触发多片快照；随后经真实 channel 注入旧版本、错 Realm、旧 Owner 状态和版本断档。客户端必须不接受伪 mark、保留正确 Owner 状态并通过 resync 恢复完整 Root 视图。继续覆盖原计划回调、义务检查点和保存重开。

该协议证明版本/会话隔离和可恢复投影，不把客户端显示自报升级为 Root Truth 或任意像素/第三方 renderer 完成证明。超大投影目前有明确上限，尚需与完整分段存储/资源预算及参与范围合同继续接合；Native/WriteSink、完整恢复器和多客户端压力验收仍待完成。

网络协议 10 与旧协议 9 不兼容，客户端和服务端需同版。Root schema 5/6、checkpoint 1、journal 3、effect 1、qualification 1/2 保持原样；没有回写原世界或改变旧成品。
