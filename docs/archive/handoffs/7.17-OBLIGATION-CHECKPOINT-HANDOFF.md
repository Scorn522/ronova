## 实现

- `ObligationCheckpoint` 保存 Root-issued revision、逻辑观察时钟、有界细节/样本/durable refs、计数/审查进度、历史候选状态和 coverage overflow。
- 检查点作为同一个 canonical Root NBT image 的字段，经过同一个 writer、checksum、原子文件替换和 ACK 路径。没有独立义务文件作为真值，没有额外 Judgment/TargetEpoch/CommitIndex 推进。
- 首次有效检查点激活 Root schema 6；无检查点的旧 Root 仍按 schema 5 编码，历史加载/事故副本不会无故改写。schema 6 缺失检查点、错误 schema、类型/边界/hash/作用域不符或降级到 schema 5 均拒绝。
- checkpoint payload 使用规范编码和独立 SHA-256，上限 2 MiB / 512 entries / 每条 4 samples 与 4 refs，验证 Realm、已有主体资格及历史代际范围。
- expected revision 防止旧写入覆盖；相同内容在 ACK 丢失后幂等恢复。未确认内容不进入 acknowledged read head。
- 没有显式解除或合法交接时，新检查点不能删除旧条目、降低计数/审查进度、遗失 durable refs 或减少 coverage gap。拒绝不破坏旧 Root。
- Coordinator 每 20 个逻辑 tick 尝试检查点，停服清理前再 flush；失败保留脏状态并重试。周期之间的新观察仍属未确认运行状态，不冒充已经持久化。
- 重启保留原始证据和摘要，但状态进入 NEEDS_REVALIDATION；恢复时钟设置验证屏障，旧观察证明不能自动重新生效。恢复 detail 使用 RECOVERY 配额，资源不足时保留 Root 检查点等待重试，不以空缓存覆盖它。

## 版本与边界

Root 最大 schema 6，checkpoint schema 1；command journal 3、effect 1、qualification 1/2、policy 3、协议 9、Native DLL 未改。r64 及更早版本不能回读已激活 schema 6 的世界，回退必须使用匹配备份。

当前 checkpoint 保留有界细节和全局 coverage gap，仍不是多层范围汇总/限制理由接力的完整实现。周期内未 ACK 的观察可能在崩溃时丢失；当前观察层没有新增 Candidate 处置权限，实际 Root gate 和原未知效果义务仍独立保留。未来新增限制必须以持久接纳为前提。
