## 实现与实际声明

- 八类 `RuntimeSurface` 统一登记，提供带 Realm/epoch、采样 revision、sourceId、scope 和有界计数的 typed observation。
- Data / Temporal / Registry / Network 接入现有 Root、构造队列、准入和 channel 诊断；当前只注册观察端口，supported/evidence 上限为 S1。Presentation / Input / Event / Resource 缺少适配器，报告 S0/UNAVAILABLE。
- 成熟度枚举覆盖 S0–S6，但没有用占位 executor 伪造 S3–S6。观察失败降低当前证据并保留最后可信记录；移除或替换 provider 后，旧记录不能充当新 provider 的当前证据。
- Network 计数明确标为 process-wide shared，不归因于当前 Realm 或任何敌方来源。资源安全是共用约束，不作为第九个攻击表面。
- `HostResourceDomain` 登记 15 个资源域，分开报告 owned accounting 和 JVM/进程总体观测。公开 JMX 提供 heap、direct/mapped buffer、metaspace、code cache、thread、class 的可用读数；缺少上限时不计算压力，缺少观测时保留 null/UNOBSERVED。
- `HostResourceGovernor` 原子预检多域请求，支持软/硬限制与 RECOVERY headroom；未登记 accounting 的分配请求拒绝。host 压力不增加 ownedUsage，也不删除 Root Truth/obligation。
- 实际接线的是构造观察与网络排队：共用 JAVA_HEAP 配额，单 slot 按 4096 字节保守记账；NORMAL 软限 8 MiB，硬限 16 MiB，配置的最低 recovery reserve 为 2 MiB。该值是配额和估算，不是实际预分配的 JVM 内存。
- 队列满时不接纳新的可选观察/排队 work，最终准入门和 Root 提交路径继续存在。完成、过期、取消、移除、诊断淘汰和清理释放 reservation；重试与保留的 dead letter 仍占额度。处理器抛错时保留 work，不把未完成工作当成已释放。
- 网络 future 完成/取消也释放尚未运行的 work；取消后的 callback 不再运行。实体观察未入队时不留下无法重试的 dedup 标记。
- `/ronova diagnostics` 输出八类表面和十五域报告；每秒至多采样一次。普通玩家界面不新增内部枚举页面。

Root schema 5、journal 3、qualification 1/2、policy 3、协议 9 和 Native DLL 未改。诊断与 governor 不获得 Root 写权限。

## 计量边界

JAVA_HEAP 的 ownedUsage 是两类已接线排队 slot 的 PARTIAL_ESTIMATE，不是 Ronova 全部 retained heap。原始观察图、缓存、Root 编码临时对象、类/loader、Native/JVMTI、平台句柄和 GPU/render 分配尚未全部接入；不得把这些域的 unknown 记成 0。

DEFAULT budgets 对未接线域只是未来分配端口的限制配置，不能证明现有外部/native 分配已受控。NORMAL 不可占用配置的恢复余量；RECOVERY 仍受硬限约束。此配额不构成宿主 OOM 或驱动安全的全域证明。
