## 生产接线

```text
TerminalLifecycle
→ DominionServerRuntime.integrateLifecycleOnce
→ LocalDominionStore
→ ShadowDurableRootStore 的原 command/qualification 校验
→ 同一 Root 文件写入 PREPARED + 兼容 lifecycle claim
→ ACK 后发放单次 EffectClaim
→ enterEffect 再检查当前 TargetEpoch / policy / Owner / 本次实例
→ 在 Root monitor 外运行原 public-death callback
→ 持久记录 EFFECT_UNKNOWN
```

- `EffectRecord` 保存稳定 EffectKey、原 authority hash/commit index、effect payload hash、policy、plan/step、attempt、状态、revision 和有界 evidence reference。
- 当前 Root 只接受注册的 `ronova:public-death/v1` / `once` 语义位置。随机重试 slot 不形成可执行入口；当前采用原 command id 作为 plan id、plan revision 1，重规划 metadata 不改变 effectKey。
- journal 索引把当前资格定位到其原 Root 命令；历史效果仍通过原命令的资格集合核验，不根据当前目标代际给旧效果续租。
- 未获 intent ACK 不发放执行许可。重复 prepare、换物理对象、恢复原 key 或复制 claim 数据，都不能获得第二次入口。
- `enterEffect` 消耗当前 JVM 内的原 claim 实例；prepare 后发生 clear 会使入场失败。该检查尚不是覆盖所有下游写入的 EnforcementLease/TOCTOU 证明。
- 普通返回、抛异常以及进程只留下 PREPARED 均不证明外部效果完成或没有发生。OPAQUE 不允许伪造 EFFECT_CONFIRMED / NO_EFFECT_CONFIRMED。
- 重启把经过校验的 PREPARED 保守恢复为 EFFECT_UNKNOWN，并由同一 writer 保存；不重发 Judgment，也不推进 TargetEpoch/DominionEpoch/commit index。
- clear/re-terminalization 保留历史未知效果。新的合法资格使用新的 command/TargetEpoch，不能覆盖旧 effectKey。
- 兼容 boolean claim 入口保留原 intent 防重复语义；已消费的 RAM grant 会释放。旧 unqualified/已 claim 数据继续走明确的 legacy 语义，不随机构造新资格或把旧 claim 改称完成证明。

通用记录/状态模型已经落地，当前生产恢复策略只启用 OPAQUE 的保留与不重放。IDEMPOTENT、QUERYABLE、COMPENSATABLE 只有合同枚举，尚无获准的生产恢复 executor。
本批没有把 `kill/discard/remove`、实体移除 callback 或任意第三方内部副作用都纳入同一 exactly-once 保证。

## 存储容量

| 约束 | 当前实现 |
|---|---|
| 文件格式 | 仍为 format 1、64 MiB NBT payload 上限 |
| Root NBT / command journal | 5 / 3 |
| effect / qualification extension | 1 / 1 |
| policy / protocol / DLL | 3 / 9 / 本批未改 DLL |
| 每个 unresolved effect | 1024 字节后续记录增长 headroom |
| 最低可用恢复余量 | 8 MiB，另计完整下一图像和恢复图像 |
| owned quota | soft 192 MiB / hard 256 MiB |
| 可观测性 | FileStore 可用空间与当前 Root/.next 文件字节；失败为 UNOBSERVED |

新 command/intent 在安装工作图像前完成编码及容量预检，包含已承诺记录的未来增长；容量拒绝不修改旧文件、创建新 intent 或触发 callback。
恢复可以使用 soft quota 留出的优先空间，仍服从硬上限；原 `.next` 会被复用，预算不重复计费它。
该 headroom 是逻辑承诺和已观察可用空间，**不是独占预分配的磁盘文件**。外部进程仍可能抢占空间，实际 force/replace 失败继续保留 UNKNOWN/pending。
单次预编码图像只可消费一次。序列化复用同一 Native snapshot payload 计算旧摘要，保留历史哈希语义并减少重复编码。

`/ronova status` 增加 effect_records、effect_unresolved、effect_reserved_growth_bytes、storage_rejections、storage_pressure。
这些是缓存/计数读取。lifecycle_unverified_claims 与新 effect 计数可能指向同一原意图，不能直接相加当成独立事件数。

## 验证

- 完整 build：68 tasks，61 executed / 7 up-to-date，1m 20s；45 SelfTests = 43 production JAR + 2 development outputs。
- 实际文件：intent 写入前失败、替换后丢 ACK、恢复继续失败、结果写入失败、旧图像保留、篡改拒绝、原 key/attempt 不变。
- 容量：注入可用空间为 0 时拒绝新 command/intent；空间恢复后用原请求继续；已接受效果的结果写失败后保留 pending 并恢复。没有通过填满用户磁盘制造压力。
- 边界：格式加未来增长、不可观测空间、soft/recovery/hard、复用暂存文件的最大格式预算。
- 延迟 callback：本地结果暂时不存在时不重放；延迟写出后依旧不伪造完整效果证明。
- 六个专用子 JVM 用 `Runtime.halt(71)` 在 BEFORE_INTENT、AFTER_INTENT、AFTER_EFFECT、BEFORE_RECEIPT_WRITE、AFTER_RECEIPT_REPLACE、AFTER_RECEIPT_ACK 中止。恢复后外部计数文件没有重复写入；AFTER_INTENT 未执行的那次保持未知，不猜测补做。
- 子进程实验使用受控 opaque 文件副作用及独立临时目录；不等于真实 Minecraft 掉落/第三方异步链已完成崩溃验收。
- 对用户两份旧 Root 副本进行只读加载检查，schema 3/journal 2 与 schema 4/journal 3 均有效；没有回写原世界或副本。
- shader 修复删除了确实未参与运算的 GbufferProjMat 声明/设置，JSON 与成品检查通过，GPU 视觉复测未执行。

成品 `3,668,789` 字节，461 ZIP entries，无重复，没有混入测试类或 Minecraft/Forge 编译桩；两个 DLL 与既有资源一致。
