## 1. 结论

r53 把 r52 的统一 preset 映射替换成了 versioned、54-key、逐项可审计的 `ProfilePresetMatrix`，并把矩阵 revision、逐项解析回执、supported/evidence 双 ceiling、不可关闭安全下限、coherent restart 与旧 policy/journal schema 迁移接入现有 StrengthPolicy/Durable Root seam。

这不是 Extreme executor 完成声明。配置请求为 `STRICT_ALL` 只表示请求强度；没有真实运行能力、证据和 ACTIVE 状态时，effective 必须降级或不可用。

## 2. 逐项矩阵

### Compatible

Compatible 共 54 项：12 项 `MONITOR`、42 项 `PROTECT_RONOVA`。

保持 `MONITOR` 的 12 项是：

- 攻击：非实体、逻辑源、恢复源、任务链、回调链、动态代码、攻击来源追踪；
- 运行时：Instrumentation、JVMTI、动态代码监视、Native 模块监视、异常调用记录。

其余攻击稳定路径、全部拦截、全部穿透后防护，以及 Java Agent、Native、本地库加载、渲染保护、关键类监视、线程连续性、后台完整性检查均为 `PROTECT_RONOVA`。

### Enhanced / Extreme / Custom

- Enhanced：54 项逐项 `RELATED_PATHS`。
- Extreme：54 项逐项 `STRICT_ALL`。
- Custom：玩家显式值；进入 Custom 时先固化当前完整解析图，普通项可关闭，mandatory safety floor 不可关闭。

## 3. 解析合同

每个 `StrengthResolutionReceipt` 至少包含：

```text
policyRevision
configuredMatrixRevision / activeMatrixRevision
option
configuredLevel / presetLevel / requestedLevel
supportedCeiling / evidenceCeiling / effectiveLevel
evidenceState / activationState
minimumFloorApplied / reason
```

约束：

```text
effective <= requested
effective <= supportedCeiling
effective <= evidenceCeiling
```

profile、matrix revision 或任一逐项配置变化都会形成新的 coherent image，并等待重启整体激活。

## 4. 持久化与迁移

- StrengthPolicy NBT schema：`1 → 2`。
- schema 2 新增 `profile_matrix_revision`。
- schema 1 仍可严格、有界读取；未知 schema/revision fail closed。
- schema 1 的 profile 与显式逐项值原样保留；`FOLLOW_PROFILE` 在迁移后按当前 revision 重新绑定预设，这是一次显式的 preset 语义升版，不把旧 plane 映射伪装成 V2.5 矩阵。
- Durable policy hash 可按来源 schema 验证，保存时写入当前 schema/hash。
- command journal 可验证旧 ConfigureStrengthPolicy payload hash，并将恢复条目规范化为当前编码。
- `DurableRootStoreSelfTest` 增加 policy 与 journal 同时迁移、receipt recovery、保存和重启重验。

## 6. exact-artifact 出口门

在具备 JDK 17、Gradle/ForgeGradle 依赖和 Windows 验证条件的构建机执行：

```text
./gradlew clean build --no-daemon
```

必须确认：

1. `build/libs/ronova-0.2.0-alpha.7.17-r53.jar` 已 reobf；
2. 42/42 分层 SelfTest PASS；
3. schema-1 policy、policy hash、journal command hash 和 receipt 在迁移后可保存并重启；
4. 未知 matrix revision、缺字段、重复 key、hash drift 全部 fail closed；
5. Compatible 12/42、Enhanced 54 related、Extreme 54 strict 与 Custom 固化在成品类上逐项复验；
6. pending restart 不允许只热切换攻击或只热切换拦截；
7. JAR 无重复项，Mixin/refmap、协议 9、资源和两个 DLL 完整，并记录 SHA-256；
8. GUI/命令不得把 requested `STRICT_ALL` 显示成未被 ceiling/evidence 证明的 ACTIVE/FULL。
