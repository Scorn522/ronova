## 实现

- `AuthorityStamp` 从同一个 acknowledged Root head 读取 SubjectKey、完整主体资格、政策版本、Owner 状态、Owner 授权版本和当前持久化健康状态。全局 epoch 用于判断投影落后，不拿它替代每个主体的版本。
- Owner 授权版本索引来自既有 BindOwner/UnbindOwner 的实际变更回执，撤销后重新授予不会让旧请求恢复有效。索引从 journal 恢复，不增加第二份权威状态或改写文件格式。
- `DeferredAuthorityTask` 保留原预期值并单次消费；拒绝资格/政策/Owner ABA、上下文失效、未确认持久化及过期任务。它只校验排队预期，不代替动作自身的权限和副作用协议。
- ActionRequest 与 BlockBreakRequest 在接收时捕获服务端资格，执行时验证相同 runtime、相同连接和当前 ServerPlayer 对象，生命周期上限 5 秒。接收线程不创建 runtime；关闭任务不会重新初始化 Root。
- Realm 检查移到收据缓存访问之前；收据和冷却缓存用弱物理身份键隔离 ServerPlayer，避免同 UUID 的不同连接/服务器共用缓存。稳定请求 ID 仍经原 Root journal 恢复。
- `AdmissionPass` 绑定物理 nonce、完整 Root 预期和投影 epoch，不能因旧缓存绕过已提交但尚未发布的 Root。构造观察队列保留入队时的 UUID/nonce/资格，过期观察被消费丢弃，不刷新成新资格任务。
- 普通和乘客 tick 均复验当前资格。已知 ACTIVE 但 incarnation 过期、局部终结标记过期或持久化/投影未就绪时，原始实体/NBT/调度登记保持可保存；不给执行 pass，实际 tick 暂停。合法 Root rebind 后可恢复。HELD 不创建 Tombstone，不调用终结副作用。
- 原始登记与资格执行分开：实体管理器 `startTicking` 保留原始调度成员，`tickNonPassenger` / `tickPassenger` 才执行当前资格门。否则 rebind 后会永久失去调度机会。

Root schema 5、journal 3、qualification 1/2、policy 3、协议 9 和 DLL 均未改；本批新增信息是运行时预期和从原回执派生的索引。
