## 实现

- 既有 `SubjectQualification` 加入可选 `SubjectRevisions`，保持同一 SubjectKey 权威记录；BindingRevision、JudgmentRevision、AdmissionTokenRevision、revokeThroughEpoch 与按 StateDomainId 的 OwnershipRevision 独立更新。
- `PhysicalIncarnationId` 带完整 SubjectKey、Root-issued sequence 和物理对象 nonce。运行时 nonce 使用弱引用的对象身份映射；相等对象或同 UUID 的新对象不会自动共享 nonce。退出释放缓存。
- 生产单目标/批量裁决携带完整目标的物理 nonce，在一次 Root 事务中完成绑定与终结，每个主体的 TargetEpoch 只推进一次；同 UUID 的冲突物理对象使批量发现返回未解决，不任意选择一个对象。
- `CommittedJudgmentGate.runQualified` 检查实际物理 nonce 和完整当前资格向量。域所有权变化即使没有推进 TargetEpoch，也会使旧入口资格失效。
- 既有 `DominionCommand` 增加 `TransitionSubjects`：带预期全局 epoch、政策与完整主体向量的 REBIND / REACTIVATE / SET_OWNERSHIP。Root 检查操作者和新 owner 的当前 Owner 资格，任一目标冲突整批拒绝；实际变更一次全局提交，无变化不推进。
- rebind 保留 JudgmentRevision，仅推进绑定、TargetEpoch 与准入资格；终结/重新激活不伪造绑定变化；域 owner 更新只推进该域版本。移除 Root Owner 时，同一事务撤销其全部域 owner，并保留递增的撤销记录。
- 收据证明请求的精确下一状态；原 ID/哈希恢复不会重新分配版本。journal 校验预期输入与已有资格历史一致，head 必须吻合完整收据。
- ownership-only 更新不替换原终结命令的 effect authority。旧 effectKey 和 EFFECT_UNKNOWN 保留；域 owner 变动不能制造第二次死亡效果尝试。

## 实机发现的范围问题

最初候选第二轮重开恢复了绑定，但新 UUID 的同类实体被拒绝生成。实际原因是旧决策政策把任何非玩家请求（包括 IDENTITY）强制扩大为 GLOBAL_LINEAGE；第一轮已产生全类型墓碑。失败记录保留在 `validation/7.17/r60-game-smoke/round-2.*`，其 JAR 哈希为 `6ce364c7b0677e44172ad9b71ee2dc5b873e98fb45b6ddb61717733ad72b425e`。

最终实现让 Java 决策入口把请求 scope 作为上限：本地提案遵守请求，旧 Native/其他 provider 不能扩大 scope、替换 subject/epoch 或绕过 actor/terminal guard。DLL 未改；这是 Java Root 对提案的约束，不声称 Native 自身已获得新的语义证明。

历史已有墓碑保持原 scope，不偷偷缩小历史 GLOBAL_LINEAGE。范围修复在新副本 `r60-game-smoke/scoped` 的 round 3/4 通过；该候选随后补齐实体类型持久化。最终成品使用 `r60-game-smoke/metadata` 的 round 5/6，在同一个新副本上执行；此前所有世界和日志均保留。显式历史 lineage 语义及完整 resolver/evidence 授权迁移仍是后续工作。

旧墓碑还用 `scope == IDENTITY` 推断 player 标记，这在允许非玩家精确身份后不再成立。现在仅当实际 player 值不同于旧推断时保存 `subject_player`，从源 SubjectIdentity 恢复正确元数据；旧记录继续使用原推断，不增加字段或修改历史 hash。Root 与 Ledger 镜像的事实比较也包含这个值。

## 格式与兼容边界

Root 外层 schema 5、journal format 3、effect 1、policy 3、协议 9 不变。资格记录在实际激活新字段时使用 extension schema 2，完整向量预期输入使用 schema 2；全 legacy 记录继续使用原 schema 1 与原哈希，不虚构历史 Binding/Ownership 版本。

首次激活新版本域从其未启用基线开始发号，不把历史 TargetEpoch 数值冒充其他域的版本。旧命令原始 hash 保留；r59 及更早 JAR 不支持回读已经写入 schema-2 资格或新 transition command 的世界，回退必须使用匹配备份。
