## 实现

- `ObligationKey` 使用 Realm-qualified TargetEpoch、固定来源入口、边类型和受保护结果。当前不接受任意类名、Mod ID 或 task 字符串作为永久来源身份；未知来源留在已知结果范围。
- `CandidateEvidence` 绑定 policy/judgment/rule revision、事件和原始依据引用、证据族及观察窗口。规则要求一条有效强证据，或两个不同族、不同事件、不同依据的有效弱证据；授权合规操作和未验证 observer 不参与准入。
- 相同语义重复观察只增加饱和计数，保留至多 4 个代表样本、4 个 durable refs 和摘要；不按重复次数升级来源关系。
- detail 上限 512，接入每条 4096 字节的估算资源 reservation；容量或资源拒绝增加 coverage overflow，保持待重验，不扩大限制范围、不创建 Judgment。
- 不兼容上下文标记 mixedContext/NEEDS_REVALIDATION，清除当前候选证明。样本过期只要求重验，不变成 PROVEN_UNRELATED 或完成。
- 主体间轮转、主体内按 key 轮转；重复洪泛不会把其他主体移到队尾。每次维护最多 8 个预算单元，交替扫描持久效果与重验 detail。
- EffectJournal 增加可重建的内存分页索引，最多返回 64 条；运行时逐页读取既有 Root unresolved effect，重复扫描同一 durable ref 不增加新事件计数。
- 准入模块通过注入的观察回调上报，保持单向依赖；计划执行报告也进入同一审查层。该层只检查和报告，不提交新攻击、撤销 Tombstone 或清理未知效果。

## 严格声明边界

生产准入 observer 的完整运行时完整性证明尚未接线，故其记录 observerVerified=false，只作为观察/待重验。Root 接受的计划或 effect journal 是已知执行事实，但单条弱事实也不会自动变成 Candidate。合同测试中的 verified witness 是受控输入，不冒充所有生产 observer 已通过 attestation。

当前细节、计数、样本和 overflow summary 是有界运行时诊断；持久 backing 是原 Root qualification/effect journal。重启会从原未知效果恢复相关审查项，但不保留所有原始准入观察或 runtime overflow 细节。完整 candidate obligation 持久化、限制理由接力、来源/lineage resolver、显式解除证明与跨表面恢复仍待实现，不能把这层当作完整义务持久库。

当前没有新增 Candidate 处置权限；现有 Root gate 始终独立执行。Candidate/观察状态不改变 Authority Truth，digest/count 不是因果证明。

Root schema 5、journal 3、effect schema 1、qualification 1/2、policy 3、协议 9 和 Native DLL 未改。
