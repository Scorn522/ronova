# 若娜瓦（Ronova）

> 历史归档（2026-09-08 整理）：保留当时的设计、实现和验证口径，不代表当前源码状态。文中的“当前”“下一步”属于记录当时。
> 当前入口：[进度](../../CURRENT-PROGRESS.md) · [有效规划](../../plans/README.md)。

一个从零独立实现的 Minecraft Forge 1.20.1 Mod，不依赖其他内容 Mod 或外部启动参数。

## 环境

- Minecraft 1.20.1
- Forge 47.4.0 或更高的 47.x 版本（构建验证版本：47.4.22）
- Java 17
- 客户端与服务端都需要安装

## 若娜瓦视觉

- 剑本体使用 `32×32` 基础贴图与灰度遮罩；一个自定义核心 Shader 负责刃内流动、边缘辉光和周期高光，不依赖 OptiFine、GeckoLib 或 Tooltip Mod。
- 物品栏图标使用 Forge `IItemDecorator` 绘制呼吸式四角微光。
- 默认 Tooltip 保留操作说明，使用近黑紫底、动态红雾、暗眼、光点、可读性暗罩和呼吸边框。
- 按住 Shift 后保留完整故事文字，眼睛完全睁开并提高红雾与边框强度。
- Tooltip 眼睛图集为五个严格等宽的 `512×256` 单元；Shader 以半像素内缩取样，避免眨眼串帧。
- 标题与正文使用思源宋体 CN SemiBold。构建默认从 Adobe 官方固定版本获取；离线构建方式见下方。

## 安装

当前加强实施入口为 [V2.6](../../plans/Ronova_7.16_Plus_JVM_Extreme_Strength_Enhancement_Master_V2.6_Internal_Root.md)。[文档修订说明](../reports/DOC-REVISION-V2.6.md) 是此前 document-only 批次记录；r54–r56 建立普通许可、claim 恢复和主体资格基础；r57 接入 OPAQUE effect journal 与存储预检，整份 V2.6 仍未完成。

将 `build/libs/ronova-0.2.0-alpha.7.17-r66.jar` 放进测试实例的 `mods` 文件夹，客户端与服务端必须同用网络协议 10。使用世界副本验证；r64 及更早版本不能回读 schema 6，回退使用匹配备份。成品哈希和验证分层见 `BUILD-RESULT-r66.txt`。

Windows x64 会自动释放并加载两个职责隔离的内嵌 DLL，不需要填写 `-javaagent` 或任何 JVM 参数：原有 JVMTI DLL 只负责完整性与重转换，R3 Root DLL 只负责快照真值、决策与投影协调。Root 不可用时保留可观测的 Java fallback；完整性 DLL 的故障域不会与 Root 状态混在一起。

按 `O` 打开“运行时主权”面板；`Native`、`early` 和 `late` 都是实际运行状态，不是装饰性开关。

## 核心能力

> 以下是项目能力与历史 release 记录的汇总，不是 r58 的完整功能实机验收清单。当前实施范围见 r58 交接；普通开关与 claim 恢复沿用 r54/r55 的已说明边界。Windows Forge、GPU、Native 与 process-tree 仍需独立证据。

- 若娜瓦：攻击目标时执行多路径裁决。
- 左键：当前维度内 64 格单目标射线，方块遮挡生效；实体来源由正常查询与独立弱拓扑索引合并。
- 长按左键：64 格方块射线，仅在新方块暴露时发送一次权威挖掘请求。
- 右键：当前维度严格球形 64 格裁决场；正常世界查询与独立拓扑索引共用同一距离判定，不再让 AABB 立方体角落混入目标。
- 潜行右键：只裁决当前维度、当前已加载的实体对象，不加载新区块。
- 持久墓碑：记录 UUID、实体类型、运行时类谱系、维度、位置和作用域；同 UUID 或同谱系替身重进世界时继续拒绝。撤销时同时清理准入缓存、终态弱身份、已加载对象 NBT 提示、服务端隔离视图和客户端投影。
- 复合实体闭包：处理乘客、载具、Forge multipart 子实体与父实体。
- 七层准入防火墙：构造与 EntityType 工厂负责观察，NBT 反序列化可在对象创建前拒绝，Forge 加入事件、ServerLevel、持久实体管理器和首次 tick 负责静默终审；同一新对象通过弱身份缓存避免重复查表，不做每 tick 全世界扫描，也不让 NaturalSpawner 因预期拒绝刷 WARN。
- 延迟重试：Admission 构造工作按物理对象最多尝试 8 次；构造器/工厂双回调先经弱身份有界去重，共享同一额度。失败项轮转到队尾，不阻塞后续对象，耗尽后移入 1,024 条有界 dead-letter 诊断区并从活动 backlog 移除，不做每 tick 全世界扫描。
- 持有者连续性：事件、Mixin、Agent、服务器直达 tick 四层入口，并按独立能力模块恢复生命、死亡标记、实体回调、世界索引、tick 列表、玩家列表、飞行和若娜瓦；移除原因与连接状态由同一策略判断，服务器运行时拒绝外部强制断线，换维度、正常主动退出和停服不受阻。授权事实只允许经 Root Gateway 提交；持剑和发送动作包都只能恢复既有授权，不能创建新持有者。
- 可靠输入通道：GLFW 鼠标边沿先进入会话化单调序号队列；服务端确认前按系统时间退避重发，同一会话序号只执行一次，不依赖游戏刻是否推进。7.16 进一步把 Realm、玩家、会话与序号派生为稳定 command id，并把动作类型绑定到不可变 payload；同序号换动作会冲突拒绝。协议 9 只在同 Realm、同玩家上下文重连时保留未确认 outbox，上下文改变会清空旧输入。服务端在重新发现目标前恢复原 durable receipt；未解决的模糊提交不会提前 ACK。
- 单次掉落结算：首次裁决执行一次死亡/掉落流程，后续终态重试不再调用伤害、死亡或掉落逻辑。
- 战利品隔离：掉落物与经验球不是战斗目标，不进入独立拓扑索引，也不受旧版错误墓碑影响。
- 索引化隔离：持久墓碑、客户端标记和实体拓扑分别使用身份、空间格、UUID 与实体 ID 索引；查询不再随历史记录做全表嵌套扫描。每个客户端登录或玩家对象替换时接收完整快照，后续裁决、UUID 撤销和全量撤销广播给全部在线客户端。
- 统一执行强度：普通生物、Boss、multipart 与第三方实体一律写入跨维度的类型/运行时类谱系禁生成规则；玩家走同一终态链并额外接收死亡界面包，但持久规则严格按 UUID，便于 `/ronova clear_uuid` 精确恢复。
- 终态隔离门：已裁决对象拒绝 `revive`、正生命值和“重新加入世界”等活状态回写；区域与已加载裁决会对仍被外部持有的旧对象重断言终态，但不会重复结算掉落。
- 派生视觉隔离：客户端对未加入世界拓扑、却继承已裁决非身份谱系的代理实体执行渲染抑制；Agent 同时覆盖 Forge 事件之外的自定义实体渲染入口。
- 外部查询出口隔离：实体感知型第三方查询帮助类只在集合或可迭代结果出口过滤隔离对象；单实体返回值、事件载体和 Forge 内部身份引用保持原样，避免被错误改写为 `null`。
- 客户端失速恢复：死亡界面、覆盖层、输入释放和本地玩家拓扑恢复使用单调系统时间窗口，不依赖游戏 tick 或帧率；卡顿不会让防护窗口停摆。
- 运行时主权面板：Mixin / 双 Agent、完整性重断言、轻量 HUD 与实际运行状态。
- 视觉反馈：服务端粒子与裁决结果 HUD；本 Mod 不创建虚拟生物，并隔离外部脱离世界拓扑的已裁决代理渲染。
- 内嵌 Windows x64 DLL：JNI 自动加载、JVMTI 能力协商、ClassFileLoadHook 与原生看门狗。
- R1 Dominion Contract：Minecraft 对象只经 `MinecraftSubjectAdapter` 转换为 loader-neutral `SubjectIdentity`；四个领域均使用不可变 Decision，Capability 使用显式稳定编号与 bit mask，Ledger 可导出带 `generation:sequence` 的不可变 Snapshot。R3.2 中，Authority、Admission、Presence 仍只读 Root 已批准的本地投影，只有显式 Judgment 进入 Native 决策源。
- R2 Projection Split：`ProjectionCoordinator` 从同一个 Snapshot epoch 原子发布 AuthorityTopology、Capability、Admission 与 Presence 投影；旧 epoch 不能倒灌。`DominionLedger` 只经 `LocalDominionStore` 持久化事实，运行热路径不再散读 Ledger。`TargetDiscovery` 只选目标，`JudgmentExecutor` 只执行已决定的裁决。
- R3 Native Root Foundation：Java 只通过固定二进制快照协议发布不可变事实；Native Root 单调接收 `generation:sequence`、拒绝旧 epoch/同 epoch 冲突并负责显式 Judgment。Java 投影按 Native epoch + 指纹确认，缺失或漂移时从 Native 快照恢复；日常 Authority、Admission 与 Presence 查询不再逐对象跨 JNI。Loader、协议、进程协调、决策源、纯 C++ 领域模型和 JNI/Windows 适配器均为独立单元。
- R3.1 Modular Composition：`DominionCompositionRoot` 显式组装每个服务器的 Root、提交总线、Projection 与 Capability Runtime。所有持久写入统一为 `DominionCommand → RootCommandBus → CommitReceipt → Projection`；Ledger 只保存事实，`SnapshotAssembler` 不再反向调用策略核心。原 531 行 `AuthorityGuard` 缩为兼容 façade，生命、Vitals、效果清理、飞行、拓扑与武器连续性由独立模块执行。
- R3.2 Component Boundaries：`SpawnFirewall`、`ClientRuntime` 与 `RonovaNetwork` 保留兼容入口，但不再同时持有决策、状态、传输和功能实现。Spawn 准入缓存与构造队列按服务器装配；客户端动作、输入、恢复独立；网络通道、五种包、服务端动作与墓碑同步独立。协议 8、包顺序和行为语义保持不变。
- R4 / L5A Semantic Lease：Native JVMTI 不再只记录“发起过重转换”，而是独立验证五个已加载核心类的移除、复活、伤害、死亡、生命和隔离查询语义门。证明按看门狗周期续租，多 ClassLoader 中任一副本失败都会使本轮降级；Java 每 20 个服务端 tick 最多读取一次不可变证明投影，攻击、准入和玩家防护热路径不跨 JNI。
- 7.14D FrameBudget / Telemetry：每个服务器拥有独立的 `FrameBudgetGovernor`；可延期的 admission、有限 retry 与 stale observation 维护按计数/时间预算有界执行，回执显式记录 `deferred`、`carryIn`、`carryOut`；RAW stale 维护只轮询有界 `ReferenceQueue` 前缀，不遍历全部 live observation；Authority/Presence 同步查询只做 telemetry，不因预算耗尽延迟或改写答案。
- 7.15 DurableRootStore Shadow：`DominionLedger(SavedData)` 继续是唯一权威写者；全新世界生成 `RealmId` 时立即标记 SavedData 待保存，`ShadowDurableRootStore` 绑定同一 `RealmId`，持久化快照哈希、生命周期回执镜像、迁移状态与 crash failpoint 诊断，并拒绝旧 epoch、同 epoch 状态冲突以及同 epoch 回执删除或改写。
- 7.16 Durable Root Cutover：Java `DurableRootStore` 晋升为唯一 durable writer；世界内 `ronova/durable-root-v1.bin` 使用有界 NBT、SHA-256、file force 和原子替换，只有该图像成功落盘后才能回 `COMMITTED`。旧 `DominionLedger` 只接收 downgrade-only SavedData 镜像，镜像失败不能撤销 Root truth。Root Snapshot 在紧凑 command journal 外只保存一次，旧 journal 格式可迁移。一个动作的全部目标通过一个 `JudgmentBatch`、一个稳定 command id 与一个 epoch 原子提交；零目标动作也可写入不推进 epoch 的 durable receipt，模糊提交按原身份恢复后最多发布一次。
- 7.16 Durable TerminalWatch：墓碑决定终态监视的逻辑寿命，HOT/WARM/COLD 只控制有界重断言频率；同 UUID/lineage incarnation 经 Admission 重新提升，只有 committed clear 才能释放，不再存在六次后永久放弃的有限 retry。Root 已提交而物理终态尚未完成时，恢复路径以 durable lifecycle receipt 约束 once-only 死亡整合并继续清除。
- 7.16 StrengthPolicy：冻结兼容、强化、极限、自定义四档与 54 个稳定能力 key；configured、active、supported、effective、evidence、activation 分离，整套变更 Root 持久化并在重启后统一激活。`/ronova strength ...` 提供当前服务端操作入口；key 存在不等于对应 7.17/L6 executor 已 ACTIVE。
- 7.17 ProfilePresetMatrix：54 个 key 使用独立 matrix revision 逐项解析；Compatible 为 12 项监控、42 项保护若娜瓦，Enhanced 逐项请求相关路径，Extreme 逐项请求全部严格。逐项回执同时报告 preset/requested、supported/evidence ceiling、effective 与 activation；Custom 固化当前完整解析图，基础权限、恢复、防回滚和循环安全不能被关闭。

## 指令

```text
/ronova give
/ronova bind
/ronova status
/ronova strength status
/ronova strength compatible|enhanced|extreme|custom
/ronova unbind
/ronova judge_loaded
/ronova clear_uuid <UUID>
/ronova clear_tombstones
```

`give`、`bind`、`unbind`、`strength compatible|enhanced|extreme|custom`、`judge_loaded`、`clear_uuid` 和 `clear_tombstones` 都需要 2 级权限；两个 status 命令只读。`clear_uuid` 可由服务端控制台执行，用于恢复被永久裁决玩家或实体的准入。持有若娜瓦不会授予 Authority；只有已经写入服务端 Ledger 的持有者才会恢复防护和动作权限。

## 实现原则

- 独立工程、开放源码，内嵌 DLL 由本项目源码构建。
- 射线攻击只做一次 broad phase，不重复进行 128 次 AABB 世界查询。
- 持久状态是结构化 SavedData，不以每 tick 全世界扫描维持结果。
- 没有范围目标数量上限；性能来自索引、弱引用清理和请求幂等，而不是削减攻击对象。
- 运行时防护使用可审计的 Mixin + 原生 JVMTI + 自动/显式 Agent 后备；只重断言目标生命周期类，并与其他 JVMTI 环境共存。
- 没有针对任何内容 Mod 的 Mod ID、注册名、物品名、装备名或实体类名特判；执行和恢复只依据运行时对象、身份与拓扑状态。
- GUI 显示 Agent 的实际装载状态，配置变更重启后生效。

## 历史 alpha.7.13 / R4 验证范围

以下条目是 alpha.7.13 历史阶段的验证记录，不是 r55 的 7.17 外部发布证明。

- Java 17 对 R0 改动类的编译、球形范围/索引/授权边界回归，以及 Forge 47.4.22 网络调用描述符检查
- 新旧字节码成员描述符比对、Forge 47.4.22 网络与 Brigadier 指令注册 ABI 回归、全成品外部调用描述符差分、`net.minecraft` 与 `com.mojang` 全映射命名空间 reobf 回归、自定义 Minecraft 子类继承成员 reobf 回归、Mixin/refmap 目标核验，以及编译桩未混入成品 JAR 的审计
- Agent ASM 注入、幂等性、移除原因传递和栈帧保持测试
- 18 个 Mixin 的 `RuntimeInvisibleAnnotations` 元数据回归测试
- 索引压力、统一强度、客户端 UI 防递归、单调时间恢复和网络会话幂等测试
- 生产 JAR ZIP、Manifest、版本、网络协议、嵌套 Hook 与内嵌 DLL 一致性检查
- `DominionLedger` 的 `SavedData.save(CompoundTag)` 覆写声明已重混淆为 Forge 1.20.1 运行时名称 `m_7176_`；对应回归会同时拒绝开发名泄漏，并验证第二遍重混淆为零改动
- Presence 快照的 `FriendlyByteBuf.Writer` 方法引用使用运行时兼容的 `BiConsumer` 擦除签名；独立回归会拒绝 alpha.7.7.1 中导致重进崩溃的专用参数签名
- R1 Contract golden test 覆盖 Subject、Decision、Snapshot、Epoch、Capability；结构回归验证 Judgment 仍进入 Root 决策源，同时 Authority、Admission、Presence 热路径禁止调用 `LocalDominionCore`
- R2 Projection golden test 覆盖原子发布、epoch 回退拒绝、Authority/Capability/Admission 投影、清墓碑重建与统计连续性；结构回归验证 Authority、Admission、Presence、网络快照、TargetDiscovery 和 JudgmentExecutor 确实走投影链
- R3 Snapshot golden test 覆盖四类 Decision、逐条 epoch、确定性 FNV/SHA-256、不可变载荷和畸形输入拒绝；同一份 Java 生成载荷会交给纯 C++ Root 模型复验解析、指纹与导出结果
- R3 Native 模型回归覆盖单调安装、旧 epoch、同 epoch 冲突、Authority 能力、四类原生决策、确认/漂移与 generation 计数；JNI 结构回归同时核验薄适配层的 10 个私有静态入口和成品 PE 导出表
- R3.1 结构回归禁止 `DominionLedger → LocalDominionCore` 与 `LocalDominionStore → ProjectionCoordinator` 依赖回流，验证 Root commit/publish 唯一写链、无变化命令不重新发布、Authority/Admission/Presence 不跨 Root、工厂观察不返回 `null`，并冻结 Capability ID 与原 `0x7ff` 位掩码
- R3.2 结构回归验证 Spawn 准入按服务器装配、客户端动作/输入/恢复隔离、网络通道/包/动作/墓碑同步隔离，并禁止三个兼容 façade 重新吸收实现依赖；动作队列回归覆盖有序发送、确认推进与新会话序号重置
- R4 回归验证语义证明只从 Native 进入独立完整性领域、每 20 tick 有界读取、五类核心字节码标记、失败隔离、多 ClassLoader 失败 latch、Windows DLL 导出与攻击/准入热路径无 JNI 回流

当前 r55 已完成完整 build 和 42 项分层验证（40 production JAR + 2 development outputs）。旧版本测试结果不转记为 r55 PASS。正式替换前在世界副本测试策略迁移、重启恢复、丢失 ACK 重放、模糊提交、多人同步与终态撤销。
