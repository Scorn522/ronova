## Scope

R3.2 is a behavior-preserving structural release. It does not add a gameplay
capability, change the Root snapshot schema, modify either Native DLL, widen a
range, change player/non-player lineage scope, or alter the five-packet wire
protocol.

The release removes three mixed-responsibility classes from the center of the
runtime while preserving their public compatibility entry points.

| Compatibility facade | Before | R3.2 ownership |
| --- | ---: | --- |
| `SpawnFirewall` | 297 lines plus process-global caches and queue | 181-line adapter over a composed per-server `SpawnAdmissionRuntime` |
| `ClientRuntime` | 420 lines with input, retry, recovery and UI state | 104-line coordinator over action, input and recovery controllers |
| `RonovaNetwork` | 564 lines with transport, packets and gameplay services | 74-line API facade over channel, packet, action and quarantine services |

## Spawn boundary

`DominionCompositionRoot` now constructs one `SpawnAdmissionRuntime` per
`MinecraftServer`. Passed/rejected weak identities and deferred construction
observations can no longer leak between integrated or dedicated server
instances in the same process.

```text
Mixin / Forge event / command
  -> SpawnFirewall facade
  -> ServerRuntimeRegistry
  -> SpawnAdmissionRuntime
       -> immutable AdmissionProjection
       -> per-server weak admission caches
       -> per-server construction queue
       -> terminal/quarantine sinks
```

Process-lifetime counters are isolated in `SpawnAdmissionMetrics`; server status
continues to read its own projection counters. `SpawnFirewall.Boundary`,
`ExecutionResult` and all existing static entry points remain available to the
18 Mixin/event/command callers.

## Client boundary

- `ClientActionController` owns the monotonic session, ordered outbox,
  exponential retry and feedback state.
- `ClientInputController` owns GLFW edges, PRIMARY/AREA/LOADED selection and the
  64-block instant-mining ray.
- `ClientRecoveryController` owns local lifecycle, vitals, abilities, topology,
  screen/overlay recovery and Agent violation callbacks.
- `ClientRuntime` only sequences these controllers and keeps the old Mixin,
  Forge and packet-handler API stable.

## Network boundary

- `RonovaChannel` exclusively owns protocol `8`, discriminator order, the
  `SimpleChannel` and both transport directions.
- `RonovaPackets` exclusively owns the five schemas, codecs and thread-boundary
  handlers.
- `ServerActionService` owns durable-authority validation, request idempotence,
  Judgment execution, receipts, logging and instant mining.
- `QuarantineSyncService` owns connected-player weak references, bounded
  snapshot chunks and append/replace/remove/clear broadcasts.
- `RonovaNetwork` keeps the former public calls as a compatibility facade.

Packet registration order and payloads remain:

1. `ActionRequest` — PLAY_TO_SERVER
2. `OwnerState` — PLAY_TO_CLIENT
3. `JudgmentFeedback` — PLAY_TO_CLIENT
4. `QuarantineSync` — PLAY_TO_CLIENT
5. `BlockBreakRequest` — PLAY_TO_SERVER

## Packaging integrity

The deterministic offline packager now prunes stale nested classes when a
top-level class is replaced. This prevents the removed alpha.7.11.1
`RonovaNetwork$*`, `ClientRuntime$PendingAction`, `JudgmentEngine$RayHit` and
`SpawnFirewall$1` classes from surviving invisibly in the R3.2 JAR.
