## Result

Alpha.7.11 restructures the R3 foundation without changing gameplay semantics. The server now has one explicit composition root, one durable mutation vocabulary, one serial commit/publish lane and one per-server capability runtime. The final install remains one Mod JAR with the same two isolated Windows x64 DLLs.

```text
Minecraft adapter
  -> DominionCommand / DominionRequest
  -> RootCommandBus
  -> DominionRootGateway
  -> CommitReceipt + immutable DominionSnapshot
  -> ProjectionCoordinator
  -> CapabilityRuntime / Executors
```

## Boundaries delivered

| Unit | Responsibility |
|---|---|
| `DominionCompositionRoot` | Wires concrete Local Root, projection, Authority state and capability modules |
| `ServerRuntimeRegistry` | Owns one composed runtime per Minecraft server lifecycle |
| `DominionRootGateway` | Loader-neutral durable Root port |
| `DominionCommand` | Stable mutation vocabulary for owner and judgment facts |
| `RootCommandBus` | Serial mutation, receipt validation, projection publication and pending recovery |
| `SnapshotAssembler` | Builds immutable snapshots from persisted facts without policy callbacks |
| `CapabilityRuntime` | Owns the explicit module list and repair scheduling |
| `AuthorityGuard` | Compatibility façade for existing Forge, Mixin and Agent entry points |

The former bidirectional dependencies are gone:

- `DominionLedger` does not call `LocalDominionCore`.
- `LocalDominionStore` does not import or publish `ProjectionCoordinator`.
- Capability modules do not mutate Root state or register independent tick handlers.
- `AuthorityGuard` does not contain lifecycle, vitals, flight, topology or inventory repair implementations.

## Capability modules

- `LifecycleContinuityModule`
- `VitalsRecoveryModule`
- `NegativeEffectCleanseModule`
- `FlightModule`
- `TopologyContinuityModule`
- `BladeContinuityModule`

Capability IDs are explicit protocol values `0..10`; declaration order no longer defines the mask. The default owner mask remains exactly `0x7ff`, so Native snapshot bytes and behavior remain compatible with alpha.7.10.

## Failure semantics

Root mutation precedes projection publication. If an installed Native Root rejects or fails a publication, gameplay does not advance to execution: `RootCommandBus` throws, counts the blocked publication and leaves `root_pending=true`. Server reconciliation retries the durable Root snapshot before permitting Native-to-Java projection repair, preventing an older Native epoch from silently overwriting the pending local commit.

## Honest remaining gate

This release is R3.1, not FULL L5. It still needs a Windows Forge smoke test for composed runtime initialization, Native Root status, owner bind/unbind, one judgment, lineage rejection, clear/recovery, save/exit/re-entry and zero `module_failures`, `root_pending`, `degraded_decisions` or ABI exceptions. Independent Native attestation of critical lifecycle enforcement remains the next strength gate after structural freeze.
